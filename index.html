1 Core Date Functions

YEAR() / MONTH() / DAY()

Extract numeric year, month, or day from a date.

YEAR([Order Date]) → 2026 MONTH([Order Date]) → 5 DAY([Order Date]) → 26
returns integer

DATEPART()

Extract any numeric component from a date.

DATEPART('month', [Order Date]) → 5 DATEPART('weekday', [Order Date]) → 3
returns integer

DATENAME()

Extract the text name of a date component.

DATENAME('month', [Order Date]) → "May" DATENAME('weekday', [Order Date]) → "Tuesday"
returns string

DATETRUNC()

Rounds date down to specified granularity. Preserves date datatype.

DATETRUNC('month', #2026-05-26#) → #2026-05-01# DATETRUNC('year', #2026-05-26#) → #2026-01-01#
returns date

DATEDIFF()

Calculates interval difference between two dates.

DATEDIFF('day', [Order Date], [Ship Date]) DATEDIFF('month', #2026-01-01#, #2026-05-26#) → 4
returns integer

DATEADD()

Add or subtract intervals from a date.

DATEADD('month', -12, TODAY()) DATEADD('day', 7, [Order Date])
returns date

TODAY()

Returns current system date (no time).

TODAY() → #2026-05-26#
returns date

NOW()

Returns current system date + time.

NOW() → #2026-05-26 14:30:00#
returns datetime

3 Common Interview Trap

❌ Wrong — Mismatched comparison

IF DATETRUNC('year', [Order Date]) = MAX([Order Date]) THEN SUM([Sales]) END

Why it fails: DATETRUNC returns 01-Jan-2026 but MAX returns 31-Dec-2026. They will never match.

✅ Fix 1 — Use YEAR() on both sides

IF YEAR([Order Date]) = YEAR({ FIXED : MAX([Order Date]) }) THEN [Sales] END

✅ Fix 2 — Use DATETRUNC() on both sides

IF DATETRUNC('year', [Order Date]) = DATETRUNC('year', { FIXED : MAX([Order Date]) }) THEN [Sales] END

4 Essential Date Calculations

YTD Year-To-Date Sales

IF YEAR([Order Date]) = YEAR(TODAY()) THEN [Sales] END

MTD Month-To-Date Sales

IF DATETRUNC('month', [Order Date]) = DATETRUNC('month', TODAY()) THEN [Sales] END

QTR Current Quarter Filter

DATETRUNC('quarter', [Order Date]) = DATETRUNC('quarter', TODAY())

PREV Previous Month

DATETRUNC('month', [Order Date]) = DATEADD('month', -1, DATETRUNC('month', TODAY()))

ROLL Rolling 12 Months

[Order Date] >= DATEADD('month', -12, TODAY())

RUN Running Sum — Last 13 Months

// Filter: [Order Date] >= DATEADD('month', -12, { FIXED : MAX([Order Date]) }) // Then apply: RUNNING_SUM(SUM([Sales]))

30D Last 30 Days

DATEDIFF('day', [Order Date], TODAY()) <= 30

FY Fiscal Year (April Start)

IF MONTH([Order Date]) >= 4 THEN YEAR([Order Date]) ELSE YEAR([Order Date]) - 1 END

10 Date Function Q&A — With Sample Answers

01 Difference between YEAR() and DATETRUNC()? ▼

YEAR() extracts the year as an integer (e.g., 2026). DATETRUNC('year') returns the first day of that year as a date (e.g., 01-Jan-2026).

Key difference: YEAR() is for simple comparisons and flags. DATETRUNC() is needed for a continuous date axis (trend lines, forecasts). Mixing them in a comparison causes a datatype mismatch error.

YEAR([Order Date]) → 2026 // integer DATETRUNC('year', [Order Date]) → 01-Jan-2026 // date
02 Difference between DATEPART() and DATENAME()? ▼

DATEPART() returns a number. DATENAME() returns text.

Use DATEPART when you need to sort or do math (e.g., weekday = 1 for Sunday). Use DATENAME when you need display labels ("January", "Monday").

DATEPART('month', [Order Date]) → 5 // integer DATENAME('month', [Order Date]) → "May" // string
03 Difference between TODAY() and NOW()? ▼

TODAY() = current date only (no time). NOW() = date + time.

Why it matters: If you use NOW() in a DATEDIFF calculation, the time part can cause off-by-one errors. For day-level comparisons, always use TODAY().

TODAY() → 2026-05-26 NOW() → 2026-05-26 14:30:22
04 Why use DATETRUNC() for trend analysis? ▼

Because DATETRUNC returns an actual date, Tableau can place it on a continuous axis. This creates a proper timeline with evenly spaced ticks — needed for trend lines, reference lines, and forecasts.

If you use DATEPART or YEAR instead, you get discrete headers — no continuous axis, no trend line, and months from different years can overlap visually.

05 Why use { FIXED : MAX(Date) } instead of TODAY()? ▼

Real-world data has a refresh lag. If data only goes up to 3 days ago, TODAY() shows an empty "current period" — misleading for users.

{ FIXED : MAX([Order Date]) } uses the dataset's actual latest date, so YTD / current month calculations always align with available data. It's also a row-level scalar — no aggregation issues when comparing.

06 Write a YTD calculation ▼
// Simple: IF YEAR([Order Date]) = YEAR(TODAY()) THEN [Sales] END // Better (uses dataset max date): IF YEAR([Order Date]) = YEAR({ FIXED : MAX([Order Date]) }) THEN [Sales] END

The second version is better for production — doesn't depend on system clock.

07 Write an MTD calculation ▼
IF DATETRUNC('month', [Order Date]) = DATETRUNC('month', TODAY()) THEN [Sales] END

Uses DATETRUNC to compare at month level — all dates in the current month get their sales included, everything else returns NULL.

08 How to do rolling 12 months? ▼
// As a filter: [Order Date] >= DATEADD('month', -12, TODAY()) // Better — using dataset max date: [Order Date] >= DATEADD('month', -12, { FIXED : MAX([Order Date]) })

Second approach won't break if data has a refresh delay. Use as a calculated field filter or context filter.

09 Running sum — how and when? ▼
RUNNING_SUM(SUM([Sales]))

How: It's a table calculation. Add via Quick Table Calculation or write the formula. Configure "Compute Using" to set direction (e.g., across months).

When: Cumulative revenue tracking, YTD progression, showing how a metric builds over time. Partitioning resets it per group (e.g., per region).

10 Fiscal year logic? ▼

For a fiscal year starting in April (common in India):

IF MONTH([Order Date]) >= 4 THEN YEAR([Order Date]) ELSE YEAR([Order Date]) - 1 END

March 2026 → FY 2025. April 2026 → FY 2026. Tableau also has a built-in fiscal year start under Default Properties, but the calculated field gives more control.

11 Compare current vs previous month? ▼

Method 1 — Calculated fields:

// Current Month Sales: IF DATETRUNC('month',[Order Date]) = DATETRUNC('month', TODAY()) THEN [Sales] END // Previous Month Sales: IF DATETRUNC('month',[Order Date]) = DATEADD('month', -1, DATETRUNC('month', TODAY())) THEN [Sales] END

Method 2 — Table calc: Use LOOKUP(SUM([Sales]), -1) with months on the addressing axis.

12 Weekend flag logic? ▼
IF DATEPART('weekday', [Order Date]) IN (1, 7) THEN "Weekend" ELSE "Weekday" END

Note: In Tableau, weekday 1 = Sunday, 7 = Saturday by default. This can change based on locale settings.

13 Continuous vs discrete dates in Tableau? ▼

Discrete (blue pill): Creates column/row headers. Each value is a separate bucket. Good for bar charts comparing Jan vs Feb vs Mar.

Continuous (green pill): Creates an axis. Values plotted on a timeline. Good for line charts. Supports trend lines, reference lines, forecasts.

Switch: Right-click the date pill → choose Discrete or Continuous.

14 Why do date comparisons fail? ▼

The #1 reason: datatype mismatch. Comparing integer to date, or row-level field to aggregate.

• DATETRUNC returns date, YEAR returns integer — can't compare directly

• MAX([Date]) is aggregate, [Date] is row-level — can't use in same IF without LOD

Fix: Same type on both sides. Use { FIXED : MAX() } if you need a row-level scalar from an aggregate.

15 Row-level vs aggregate calculation difference? ▼

Row-level: Runs on every row. Example: [Sales] * [Discount], YEAR([Order Date]). No aggregation needed.

Aggregate: Runs after data is grouped. Example: SUM([Sales]), MAX([Order Date]). Requires a level of detail (what's on Rows/Columns).

Why it matters: You can't mix them. IF [Order Date] > MAX([Order Date]) fails. Use LOD expressions to bridge the gap.

16 How to handle NULL dates? ▼
// Replace NULL with fallback: IFNULL([Ship Date], [Order Date]) // Flag missing dates: IF ISNULL([Ship Date]) THEN "Missing" ELSE "Has Date" END

NULL dates are excluded from most calculations by default. Handle them explicitly if your analysis needs them.

17 How to convert a string to a date? ▼
// If format is known: DATEPARSE("dd-MM-yyyy", [Date String]) // If standard format: DATE([Date String])

DATEPARSE is not available on all data sources (missing for Tableau extracts from Excel). If unavailable, use MAKEDATE() by splitting the string into year, month, day parts first.

18 How to calculate age or tenure from a date? ▼
// Age in years: DATEDIFF('year', [Birth Date], TODAY()) // Tenure in months: DATEDIFF('month', [Hire Date], TODAY()) // Days since order: DATEDIFF('day', [Order Date], TODAY())

DATEDIFF counts date boundaries crossed, not exact elapsed time. For precise age, add logic to check if the birthday has passed this year.

11 Golden Rules

⚡ Always Think About These 5 Things

  • Datatype — Is the result a Date or Integer? Mismatches break comparisons.
  • Granularity — Are you comparing at the right level (day vs month vs year)?
  • Aggregation level — Is it row-level or aggregate? Mixing them causes errors.
  • Row-level vs Aggregate — Can't compare a row-level field with an aggregate directly without LOD.
  • TODAY() vs { FIXED : MAX } — Real dashboards have stale data. Use dataset max date.

19 Table Calc Q&A — With Sample Answers

01 Running Total vs Window Sum? ▼

Running Total (RUNNING_SUM) = cumulative progression. Values: 100, 300, 450.

Window Sum (WINDOW_SUM) = same grand total repeated on every row. Values: 450, 450, 450.

Use Running Total when showing how something builds over time. Use Window Sum when you need a denominator for percent-of-total.

02 LOOKUP vs PREVIOUS_VALUE? ▼

LOOKUP() fetches an existing aggregated value from another row. It reads what's already there.

PREVIOUS_VALUE() uses the result it computed for the previous row — it's recursive. First row uses the seed value.

LOOKUP(SUM([Sales]), -1) // reads existing PREVIOUS_VALUE(0) + SUM([Sales]) // recursive

Use LOOKUP for simple comparisons. PREVIOUS_VALUE only for chained/recursive logic.

03 Can table calcs affect performance? ▼

Yes. Table calcs run in the Tableau layer, not in the database. The DB returns the full result set, then Tableau applies calcs in memory.

If your query returns 1M rows, all 1M rows go through the table calc engine. This is why large cross-tabs with multiple table calcs are slow.

Fix: Use context filters to reduce result set before table calcs. Or replace with LOD expressions where possible — LODs push computation to the database.

04 What is Partitioning vs Addressing? ▼

Addressing = direction the calculation moves. "The path."

Partitioning = groups that restart the calculation. "The fence."

Example: Running total across months (addressing = Month), reset per region (partitioning = Region).

Configure via "Compute Using" — the fields you select are addressing; everything else is partitioning.

05 Where do table calcs sit in the order of operations? ▼

At the very end: Extract → Data Source → Context → Dimension → Measure → Table Calcs.

If you put a table calc on Filters shelf, it filters AFTER the query runs. The data was already fetched. A Top N filter using RANK() still fetches all data — it just hides rows at display level.

06 TOTAL() vs WINDOW_SUM()? ▼

Both give a sum across the partition. But TOTAL() always sums the entire partition.

WINDOW_SUM() accepts start/end parameters so you can sum a sub-range.

TOTAL(SUM([Sales])) // always full partition WINDOW_SUM(SUM([Sales]), -2, 0) // last 3 rows only
07 How to show Top N using table calcs? ▼
// Create calculated field: RANK(SUM([Sales])) // Drag to Filters shelf → range 1 to N

Important: This is a table calc filter — runs after the query. All data is still fetched. For better performance, use a regular Top N filter, Sets, or context filter.

08 How does WINDOW_AVG(-2, 0) work? ▼

-2, 0 means: go 2 rows back from current, up to current row (0). Averages 3 rows: current + 2 previous.

First 2 rows don't have enough previous rows — Tableau averages whatever is available. To show NULL instead:

IF INDEX() >= 3 THEN WINDOW_AVG(SUM([Sales]), -2, 0) END
09 Different RANK types in Tableau? ▼

RANK() — Standard. Ties get same rank, next is skipped: 1, 2, 2, 4.

RANK_DENSE() — Dense. Ties same, next NOT skipped: 1, 2, 2, 3.

RANK_MODIFIED() — Ties get the higher rank: 1, 3, 3, 4.

RANK_PERCENTILE() — Returns percentile position (0 to 1).

10 Table Calc vs LOD — when to use which? ▼

Table Calcs: Operate on the result set after query. Depend on what's in the view (Rows/Columns pills).

LODs: Operate at the data source level. Push computation to the database. Don't depend on view layout.

Use Table Calcs for: running totals, moving averages, ranking, % of total — things needing the visible layout.

Use LODs for: customer-level aggregates at order level, cohort analysis, different granularity than the view.

21 LOD Expressions — Q&A

01 What are LOD Expressions? ▼

LOD (Level of Detail) expressions let you control the granularity of a calculation independent of the view. They compute at the data source level.

Three types: FIXED (compute at a specific level), INCLUDE (add a dimension), EXCLUDE (remove a dimension).

{ FIXED [Customer] : SUM([Sales]) } { INCLUDE [Product] : AVG([Profit]) } { EXCLUDE [Region] : SUM([Sales]) }
02 FIXED vs INCLUDE vs EXCLUDE — when to use? ▼

FIXED: Ignores the view. "Total sales per customer, no matter what's on the view." Used for: customer lifetime value, cohort dates, first purchase date.

INCLUDE: Adds a dimension the view doesn't have. "I'm showing Region, but need per-customer averages." Adds Customer temporarily.

EXCLUDE: Removes a dimension the view has. "I'm showing Month, but want annual totals." Removes Month from the calc.

03 Do dimension filters affect FIXED LOD? ▼

No — classic interview trap. FIXED LODs are evaluated before dimension filters in the order of operations. Only context filters, extract filters, and data source filters affect them.

If you want a dimension filter to affect a FIXED LOD, promote it to a context filter (right-click → Add to Context).

04 Find each customer's first order date? ▼
{ FIXED [Customer ID] : MIN([Order Date]) }

Returns the same first-order date for every row of that customer, regardless of the view. Common in cohort analysis — group customers by when they first purchased.

05 Average of per-customer totals (nested aggregation)? ▼

You can't nest aggregates in Tableau (no AVG(SUM(…))). LOD solves this:

// Step 1: Each customer's total (row-level result) { FIXED [Customer ID] : SUM([Sales]) } // Step 2: Average those totals AVG({ FIXED [Customer ID] : SUM([Sales]) })

Step 1 produces a row-level value. Step 2 aggregates those values normally.

22 Filters & Performance — Q&A

01 What is a Context Filter? ▼

A context filter creates a temporary table of filtered results. All other filters run on top of it. Evaluated before dimension filters and FIXED LODs.

Use when:

• You want a dimension filter to affect a FIXED LOD

• Top N filter should work within a subset (Top 5 in East region only)

• Performance optimization — reduces working set for subsequent filters

02 Extract vs Live connection — performance? ▼

Live: Queries the DB directly every time. Good for real-time data. Slower if DB is slow or network has latency.

Extract (.hyper): Snapshot stored locally in Tableau's columnar format. Much faster for queries, works offline. Data only as fresh as last refresh.

Rule: Use extracts where slight staleness is OK. Use live for real-time monitoring.

03 How to improve dashboard performance? ▼

Data layer: Use extracts, reduce row count, aggregate to needed granularity, hide unused fields.

View layer: Keep marks under 10K. Avoid wide cross-tabs. Use context filters. Minimize INCLUDE/EXCLUDE LODs (slower than FIXED).

Design layer: Fewer sheets per dashboard. Avoid redundant calcs. Use Performance Recorder (Help → Settings → Performance Recording).

04 Data Source filter vs Extract filter? ▼

Extract filter: Applied when extract is created. Data not matching is physically excluded from .hyper file. Most efficient.

Data source filter: Applied at query time. Reduces what's sent but full dataset still exists in source.

Use extract filters for large-scale exclusions (old years, inactive records). Use data source filters for row-level security.

23 Dashboard & Design — Q&A

01 What are Actions in Tableau? ▼

Actions add interactivity to dashboards:

Filter Action: Clicking a mark filters other sheets. Most common.

Highlight Action: Highlights related marks across sheets.

URL Action: Opens a web page — drill-through to external systems.

Go to Sheet: Navigates between dashboards.

Set Action: Clicking adds/removes values from a set — powerful for dynamic filtering.

Parameter Action: User clicks update a parameter — what-if scenarios.

02 Blending vs Joining? ▼

Join: Combines data at row level before aggregation. Done in Data Source tab. Can cause duplication if granularity doesn't match.

Blend: Combines data after aggregation. Secondary source aggregated to match primary's granularity. Useful when sources can't be joined.

Modern alternative: Use Relationships (2020.2+) — they handle granularity mismatches automatically. Now the recommended approach.

03 What are Sets? ▼

A Set is a custom subset — creates a binary IN/OUT classification.

Fixed Set: Manually pick members (e.g., "East" and "West").

Computed Set: Based on a condition (e.g., "Top 10 by sales").

Combined Sets: Union or intersection of two sets.

Set Actions: Users dynamically add/remove members by clicking. Very powerful for interactive analysis.

04 Parameter vs Filter — what's the difference? ▼

A Parameter is just a value holder (number, string, date). Does nothing alone — must be referenced in a calculated field, filter, or reference line.

A Filter directly restricts which data is shown.

Use parameters for: Dynamic Top N, what-if analysis, measure swapping, dynamic date ranges.

// Dynamic Top N: RANK(SUM([Sales])) <= [Top N Parameter]
05 How to publish and share dashboards? ▼

Tableau Server / Cloud: Publish from Desktop → Server → Publish Workbook. Set permissions, schedule extract refreshes, organize into projects.

Tableau Public: Free, but all data is public. Good for portfolio.

Key concepts: User roles (Viewer/Explorer/Creator), row-level security via user filters, extract refresh schedules, subscription emails for automated delivery.
